# 版本与 Git 规范

> Git 整体由 AI 自主管理：提交、推送、决定版号、写更新日志均由 AI 按专业标准执行，用户只在需要时干预。
> 唯一硬性要求：**提交描述必须用中文**。

## 一、日常提交

- 小步提交，可回退易审查，只在任务完成后提交本次涉及的改动。
- 描述格式：`[类别] 具体目标`，类别用 `[修复] [新增] [优化] [重构] [文档] [配置] [发布]`。
- 完成后推送。

## 二、更新日志

- `更新日志.md` 只在发版时统一编写：用 `git log` 统计自上次发布以来的提交，合并成 1~3 条用户可感知的改进（每条 15 字内），写入新版本块。
- 日常改动不写入更新日志。

## 三、发版

- 改动累积到合理程度（或用户要求）时：决定版号 → 写更新日志 → 提交 `[发布] 发布 vX.Y.Z` → 推送。
- 版号按改动性质升补丁号；较大功能新增可升次版本号。
- 默认不打 tag，tag 由用户发布后自行处理。
