# Git 提交信息规范

- 提交信息采用“[类别] 具体的修改目标”这种紧凑的格式
- 类别必须包含：`[修复]`、`[新增]`、`[优化]`、`[重构]`、`[文档]`
- 摘要描述写清楚改了什么，达到了什么目标，别写废话！因为**行为往往很短而且很多，提交信息必须方便后续精准提取给用户看更新日志！**
- 编写代码摘要，要求足够细节，通常保持在一行，必要时再分行说明
- 不要使用英文提交前缀

## 推荐示例

- `[修复] 修复视频列表网格视图在宽屏下显示异常`
- `[修复] 修复移动端返回按钮点击无效的问题`
- `[优化] 记住历史集数并自动跳转到对应集数`
- `[新增] 注入 115 原画清晰度解析`

## 拒绝示例

- `[新增] 优化视频列表并修复预览异常` (多个意图混杂之后发版时不知道新增了什么)
- `[修复] 修复问题` (无价值)
- `[优化] 优化代码` (无价值)
