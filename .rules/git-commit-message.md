# Git 提交信息规范

- 提交信息采用 **“[类别] 具体的修改目标”** 这种紧凑格式。
- 严禁使用英文提交前缀（如 `fix:`, `feat:`），必须使用以下中文类别前缀之一：
  - `[修复]`：修复 Bug、崩溃或非预期行为
  - `[新增]`：添加新功能或新特性
  - `[优化]`：性能、UI/UX 细节或逻辑优化
  - `[重构]`：不影响功能的前提下调整代码结构
  - `[文档]`：更新 README、CHANGELOG 或规则配置
  - `[配置]`：修改 package.json 依赖、构建设置、环境变量
  - `[发布]`：专门用于发布新版本的提交（例如升级版本号）

## 编写原则
1. **简明易读**：摘要需直接描述改动原因和结果，让用户/开发者能一眼看懂，避免空话（如 `[修复] 修复问题`）。
2. **单一意图**：每次提交应只做一件事，避免把不同意图的修改（如修复 Bug + 顺手重构）混在一个提交中。
3. **方便提取**：提交日志是后续直接提取并生成 Changelog 的唯一来源，叙述需清晰得体。
