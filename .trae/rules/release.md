# 版本更新说明规则

## 变更识别与提取
- **跨版本比对**：通过 `git log <上一个tag>..HEAD` 获取自上个正式版本以来的所有提交记录。
- **获取上个版本**：使用 `git describe --tags --abbrev=0` 确定上一个发布标签。

## 更新说明生成规范
- **面向用户**：发布说明默认写给用户看。从原始提交记录中提取“用户能感知到”的价值，过滤掉内部重构细节、代码结构调整、ESLint 等纯技术内容。
- **分类汇总**：根据提取出的关键更新，将变更系统性地分为以下几类（按需包含）：
  - 🚀 **新功能**
  - 🐞 **问题修复**
  - ⚡ **体验优化**
- **合并同类项**：将多次相关修改（例如 UI 的连续几次微调、某功能的多次修复）合并为一条连贯、易读的更新说明，避免碎片化和流水账。
- **历史覆盖**：生成的说明必须覆盖两个版本之间的完整闭环，让用户知道这个版本到底积累了哪些改进。

## 执行流程
1. **升版号**：更新 `package.json` 中的版本号。
2. **生成说明文件**：基于跨版本提交记录，按照上述规范生成文本，并将其保存在 `release/` 目录下（命名格式例如 `release/changelog-v1.7.4.md`）。
3. **完成提示**：生成完毕后，提示用户说明文档已就绪。后续打包压缩和最终发布的动作交由用户手动完成即可。
