# 迭代否决项

记录**已定论 / 已排除 / 已否决**的事项。做迭代规划、测试补强、审查建议时按需对照，不再重复评估。
项目基调：私域小范围发布、稳定优先；发展由「深度审计 + 用户真实反馈」双轨驱动。

---

## 一、已定论（行为结论，不再处理）

- 双击网盘列表行（含勾选框 / 空白区）打开 115 官方播放器 = **115 原生行为**；扩展仅由文件名 / 缩略图触发自身播放器。

## 二、已排除（用户明确不做）

- **删除一律不弹二次确认**：用户快速删除习惯，115 有回收站兜底；**所有删除入口都不弹确认**。
- **倍速不记忆，切集重置为 1x**。
- **快捷键保持硬编码基础即可**，不做可配置化。
- **播放列表拖拽排序不做**：列表与网盘目录对应，服务端按文件名排序。
- **无损降级记忆不做**：已有画质选择记忆，重复且收益低。
- **下载拦截体验闭环不做**：用户很少用，有反馈再捡起。
- **媒体墙分区排序（文件夹/图片/视频）保持默认，不做自定义配置开关**：黄金自上而下动线，符合直觉，避免过度设计与虚拟滚动冲突。
- **体验增强暂缓（按需再议）**：字幕样式调节、列表搜索、双击全屏。

## 三、已否决（技术评估不做）

- 旧版播放器遗留的性能 / 架构类优化项（悬停请求队列、封面预热数量收敛、HLS 卡顿看门狗，以及各类缓存 / LRU / 内存 / 日志 / 边缘场景琐项）：收益过低或属边缘场景，一律不做；除非出现**真实卡顿反馈**再议。

## 四、项目基调

### 1. 执行纪律（永久）

- 小步提交、可回退易审查；**只做当前请求涉及的改动，不顺手重构无关代码**。
- 日常提交严禁动版本号与 Changelog，仅在发版指令时统一维护。

### 2. 稳定性契约（永久）

- **用户能感知到的现有行为 = 必须保留**：实现方式可换，行为结果不能默默变。
- 改动若影响功能完整性 / 使用习惯 / 跨页面联动，**必须先说明影响并获同意**再改。

### 3. 探索策略

- **决策由证据驱动**（深度审计 + 用户反馈），不默认拒绝、也不无脑加功能。
- 新建议流程：**分级（高/中/低）→ 进迭代计划 → 试点实现 → 回顾验证**；高价值主动做，低价值记入暂缓不硬凑。
