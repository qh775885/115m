# 115m 2.0 迁移计划

本文件是 115m 2.0 的**唯一计划文档**，合并了「大步骤（战略阶段规划）」与「小步骤（播放器迁移进度）」两层。
播放器视觉与架构标准见 `docs/播放器.md`。

---

## 一、战略基调

**双轨驱动 · 现代化工业底座重铸 · 极简轻快实用**。

1. **主线（Master）绝对稳定**：
   - 保持现有稳定版本的轻量维护，禁止在旧播放器（Artplayer）脆弱的 CSS / DOM 上做缝合修补。
   - 用户日常使用与 Bug 修复不受大改影响，基线测试与打包必须始终全绿。
2. **支线（Feature Branch）独立演进**：
   - 全新播放器及后续多媒体体系的大改，严格在独立分支（`feat/v2-vidstack-player`）中单向演进。
   - 拒绝闭门造车与手撕轮子，技术升级全部基于经过验证的现代工业级开源方案（播放器选 **Vidstack**，看图器选 **PhotoSwipe**）。
3. **实用轻快优先，严守原生安全边界**：
   - 拒绝花哨无用的视觉噱头（氛围光晕、GPU 画质着色器等一律剔除）。
   - 大图查看器追求极致轻快：秒开、切图顺畅、无级手势缩放跟手。
   - 媒体墙与文件夹封面：**严守原生优先与零风控铁律**，100% 沿用 115 原生封面与缩略图，不发任何未授权第三方请求。

## 三、大步骤 · 阶段规划

### 阶段一：视频播放器重铸（Vidstack 独立支线）

- **Phase 0 实验沙盒**：验证 Vidstack 在 WXT + MV3 下的加载与打包可行性。
- **Phase 1 交互对齐**：居中主控簇、横向音量胶囊、时间进度轴、快捷键与全屏。
- **Phase 2 业务融合**：原画 / HLS 混播管线、播放状态与历史、业务图层（顶栏 / 侧边选集 / 旋转）。
- **Phase 3 验收合流**：真机压测、降级开关、测试补全、经零验收后合入主线。

### 阶段二：全媒体套件生态升级（后置推进）

1. **大图查看器轻量现代化重构**（PhotoSwipe v5）：淘汰手写阻尼矩阵数学公式，接入零外部依赖轻量引擎。
2. **文件夹封面与媒体墙现代简约排版**：原生封面优先、零风控；现代极简卡片；探索虚拟滚动解决大目录卡顿。
3. **设置面板开关中枢**：在左侧栏设置面板中提供「列表封面预览」「媒体墙模式」总开关，交用户按需控权。

## 六、工程纪律与验收红线

1. **零污染原则**：任何针对新播放器的预研与编码，严禁修改主线业务逻辑。
2. **不发明设计**：严格遵循既定设计语言与 Vidstack 标准，拒绝无序 CSS 补丁。
3. **功能完整性**：老播放器支持的文件移动、收藏、选集预览、直链鉴权，新播放器一个都不能丢。
4. **验证全绿方可收尾**：合并主线前，`typecheck`、`lint (0 error)` 与单元测试必须全部通过。

## 七、旧代码解耦与归档策略

**核心思想**：解耦靠"消除跨目录引用"，不靠"搬文件夹"；v2 必须自包含。

### 现状

- v2 运行时仍 `import` 旧 `core/*`（`player-services`、`playlist-url` 及其依赖链），这是唯一的耦合点。
- 旧 `player.ts`、旧 UI、旧 CSS 在 v2 中已零引用。

### 解耦步骤

1. **实装期**：把 v2 需要的旧业务模块**迁进 `src/player/v2/adapters/`**（连同测试），import 改为指向自己人。
2. **迁完后**：v2 对旧 `src/player/` 零引用，完全自包含。
3. **合流后（阶段 4 完成）**：在仓库内新建 **`V1` 归档文件夹**，将旧代码整体挪入，作为后期参考。
4. **清理**：待后续版本推进、确认长期无用后，再删除归档。**1.9 正式版（`E:\qh775885\115m`）与 git 历史本身即为永久归档**，v2 内不长期保留残骸。

### 红线

- 严禁把旧代码长期堆在 `src/` 里（会被搜索、打包、误改）。
- 归档文件夹（`V1`）**不得参与构建**，且不得被 v2 运行时引用。
