# 播放器规范

## UI 和样式规范

- **禁止内联样式**：禁止在 TS/JS 里使用 `style.cssText` 狂写一堆的布局和颜色样式，所有 UI 相关的样式应该写到 `src/player/core/css/` 对应 CSS 文件中。
- **沿用 CSS 变量**：尽可能使用 `player-skin.css` 中定义的 `--m115-*` 变量来控制字号尺寸、圆角、颜色、阴影等全局统一性。
- **毛玻璃与颜色槽**：控制条背景、菜单面板的背景底色统一使用黑色半透明（如`rgba(24, 26, 30, 0.96)`），配合毛玻璃效果（如`backdrop-filter: blur(16px)`）。
- **PC 端交互体验**：
  - 按钮或菜单项增加平滑的 Hover 态过渡（如 `.15s` 或 `.16s`）。
  - 所有控制条层使用防穿透的半透明样式，防止遮挡系统默认滚动条。
- **层级管理**：在编写叠加元素时，参考全局 `ui-layer.ts` 中定义的 `z-index`，或在 `ui-layer.css` 中统一注册，防止业务代码到处乱写 `z-index`。

## 架构与逻辑规范

- **模块化解耦**：优先复用 `src/player/core/*` 模块，不要把逻辑都堆在一个文件里。
- **职责划分**：修改前搞清楚这是 UI 问题、状态问题、数据源问题还是消息问题。
- **小步验证**：针对播放器这类样式和页面结构复杂的模块，要改小模块就要马上看效果，切勿一次性改一条长链路再去看。
- **释放销毁**：注册的任何事件流在播放器销毁时，必须回到销毁勾子中解除绑定。
