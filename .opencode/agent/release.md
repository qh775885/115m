# 版本更新说明规范

## 更新日志提取
- **找准版本起点**：通过 `git log <上一个tag>..HEAD` 提取最严格格式版本号以来的所有提交记录。
- **获取上个版本**：使用 `git describe --tags --abbrev=0` 确定上一个发布的标签。

## 更新说明生成规范
- **面向用户**：更新说明默认写给用户看，不要原样照抄提交记录。提取让用户能感知的核心价值。不要在说明里暴漏细节，例如重构逻辑或 ESLint 等代码层面的内容。
- **归类清晰**：提取出有价值的关键事件，将它们系统的分为几大类（建议使用对应表情）：
  - 🚀 **新功能**
  - 🐛 **问题修复**
  - 💡 **细节优化**
- **合并同类项**：将零散的修改，比如 UI 对齐或者微调，或某一个功能的多次修改，合并为一个精炼、易读的更新说明，不要碎片化流水账。
- **历史跨越**：生成的说明如果覆盖了前几个版本之间有断层或没有发版，用户不知道，要将几个版本的精华合并在一起。

## 执行操作
1. **升版本号**：修改 `package.json` 中的版本号。
2. **更新 Changelog**：将新版本的提交记录，按分类规范、文本美化后，追加或插入到根目录的 `CHANGELOG.md` 中。
3. **文本展示**：在最后输出时展示给用户更新说明，要求文本精美，排版清晰，方便用户直接复制粘贴。
